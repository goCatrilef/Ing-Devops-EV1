# Código de Conducta

Este proyecto fue desarrollado de manera individual para la Evaluación N°1 de la asignatura Ingeniería DevOps.

El objetivo de este archivo es definir buenas prácticas de trabajo y mantener un desarrollo ordenado, responsable y profesional.

## Principios

#   No desplegar directamente a MAIN

- Mantener una comunicación respetuosa en los comentarios, commits y Pull Requests.
- Trabajar de manera ordenada utilizando la estrategia de ramas definida.
- Evitar cambios directos sobre la rama `main`.
- Mantener trazabilidad de los cambios mediante commits claros.
- Revisar los cambios antes de realizar un merge.
- Verificar que GitHub Actions finalice correctamente antes de integrar cambios.
- Mantener la documentación actualizada.
- Evitar incluir credenciales, claves o información sensible dentro del repositorio.

## Buenas prácticas

Durante el desarrollo se debe:

1. Crear una rama para cada nueva funcionalidad o corrección.
2. Realizar commits pequeños y descriptivos.
3. Utilizar Pull Requests para integrar cambios.
4. Revisar el contenido del cambio antes del merge.
5. Mantener estable la rama `main`.
6. Utilizar variables secretas de GitHub para datos sensibles.

## Responsabilidad

El responsable del repositorio debe procurar que cada cambio mantenga la estabilidad del proyecto y respete las convenciones definidas en la documentación.

El propósito es mantener un flujo de trabajo claro, trazable y alineado con buenas prácticas DevOps.
